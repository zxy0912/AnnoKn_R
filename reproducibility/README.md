## Data dictionary

This dictionary describes the prepared inputs read by the core GTEx, Height/SCZ, and real-genotype simulation scripts. Dataset locations and filename patterns are in [`config/paths.tsv`](config/paths.tsv). Field names below are case-sensitive; GWAS readers additionally require the stated column order. These are input-format descriptions, not bundled datasets. Exact source releases and preprocessing provenance still require confirmation where noted; auxiliary biological-validation reference tables are outside this core-input dictionary.

### Genotypes and reference panels

`gtex_plink`, `ukbb`, `reference_plink`, and `cross_ancestry_plink` use matching PLINK `.bed/.bim/.fam` files. `.bed` stores genotypes; `.bim` has six columns (chromosome, variant ID, genetic position in cM, physical position in bp, allele 1, allele 2); `.fam` has six columns (family ID, individual ID, paternal ID, maternal ID, sex, phenotype). Both text files have no header. Their row order defines the variants and samples in `.bed`. See the [official PLINK format reference](https://www.cog-genomics.org/plink/1.9/formats).

The scripts use `genio::read_plink()`: `X` is initially variants by individuals, with genotype counts and missing calls represented as `NA`; `bim$id`, `bim$pos`, `bim$alt`, and `bim$ref` identify variants, positions, and alleles. Genotypes are transposed to individuals by variants for fitting. Keep IDs and allele coding consistent with the summary statistics; the labels `alt`/`ref` must not be used alone to infer the genome reference allele. GTEx variant IDs are split as `chr_pos_ref_alt_build` when mapping to annotation SNP IDs.

All positional joins require a common genome build. GTEx mapping inputs are configured for GRCh38/hg38. Supplementary S7.5–S7.6 describe Height/SCZ GWAS coordinates as GRCh37/hg19, whereas S7.2 describes a GRCh38 real-data reference panel. The exact reference files or coordinate conversion used for each GWAS analysis must therefore be confirmed; these fitting scripts do not perform liftover.

### GTEx expression, gene coordinates, and annotations

The readers in [`real_data/gtex/revision/fit_annotations.R`](real_data/gtex/revision/fit_annotations.R), the expanded-annotation fits, and the validation fits use the following inputs.

| Input | Fields and meaning | Matching / interpretation |
| --- | --- | --- |
| `gtex_expression`: `<tissue>.adj_expr` | Header and exactly two columns: first `individual` (sample/donor identifier), second a numeric covariate-adjusted expression value for one gene and tissue. The second header is replaced by the reader. | IDs are shortened to the first two hyphen-separated components, then matched to genotype sample IDs. Expression and genotype rows are reordered together. S7.3 describes adjustment for age, sex, five genotype PCs, and five PEER factors; these files contain adjusted values, not raw counts. `gtex_diagnostic_expression` uses the same layout. |
| `gtex_gene_coordinates` / `gtex_null_gene_coordinates`: `chr_<chr>_ct_<tissue>.txt` | Headered gene table: `ensembl_gene_id` (gene ID), `transcript_biotype` (e.g. `protein_coding`, `lncRNA`), `start_position` and `end_position` (numeric gene coordinates in bp), `folder_names` (expression subdirectory). Metadata may also include `hgnc_symbol` and `chromosome_name`. | One retained row per Ensembl gene ID. The fits use variants strictly inside the gene interval extended by 250,000 bp on each side. Gene coordinates must use the genotype build. |
| `gtex_variant_coordinates`: `chr<chr>_selected.txt` | Headered mapping table; required fields are `end` (numeric SNP coordinate) and `snp` (annotation SNP ID, typically rsID). The original layout also includes `chr` and `start`. | The reader matches genotype positions directly to `end`, then matches `snp` to annotation `SNP`. Preserve this coordinate convention; no offset conversion is applied. |
| `ldsc_annotations`: `baselineLD.<chr>.annot.gz` | Gzipped, headered table with one row per SNP. Standard metadata are `CHR` (chromosome), `BP` (bp), `SNP` (ID), `CM` (cM), followed by numeric annotation columns. | The three-annotation fits select `Promoter_UCSC` (promoter membership), `Enhancer_Hoffman` (enhancer membership), and `TFBS_ENCODE` (transcription-factor binding-site membership), coded 0/1. Promoter-only fits select the first. Expanded fits retain the named binary/continuous fields selected by `cats` in the driver. |

The [LDSC annotation format](https://github.com/bulik/ldsc/wiki/LD-File-Formats) documents the standard metadata and numeric annotation layout. The configured resource is baselineLD v2.2 on GRCh38; the exact release and expanded annotation definitions must be supplied with the chosen resource. In `type = 3`, the code excludes columns 1, 2, 4, and 5 by position and expects `SNP` to remain first; preserve the original column layout, including the fifth baseline column. Annotation rows are reordered to the selected genotype SNPs, the ID column is removed, and missing annotation entries are replaced by their column means. An entirely missing annotation column is not a usable input.

### Height and SCZ summary statistics

Inputs are prepared, tab-separated tables with a header. The readers overwrite the column names by position, so changing only the header does not change the interpretation. `Chromsome` below is the spelling used in the code.

**Height:** `height_gwas/GIANT_HEIGHT_YENGO_2022_GWAS_SUMMARY_STATS_<ancestry>` (`AA` in filenames corresponds to `AFR` in the analysis). The target-ancestry reader in [`fit_single.R`](real_data/height/revision/fit_single.R) and [`fit_additional_seeds.R`](real_data/height/revision/fit_additional_seeds.R) expects exactly 11 columns:

| Position | Assigned name | Meaning / type |
| --- | --- | --- |
| 1–2 | `SNPID`, `SNP` | Variant identifiers; `SNP` is the character key used to join ancestries. Preserve the supplied identifier encoding. |
| 3–4 | `Chromsome`, `Position` | Chromosome number and physical position in bp. |
| 5–6 | `EffectAllele`, `NonEffectAllele` | Effect and other allele, as nucleotide strings. |
| 7 | `EffectAF` | Effect-allele frequency, numeric in [0, 1]. |
| 8–9 | `Beta`, `SE` | Signed effect estimate for `EffectAllele` and its positive standard error on the same trait scale. The reader forms `Beta / SE`; confirm the trait scaling from the source file. |
| 10 | `Pval` | Association p-value, not a negative-log value. |
| 11 | `Neff` | Per-variant sample-size input, positive numeric; regional medians are used by some fits. |

The other-ancestry Height reader labels columns 6–7 in the opposite order and column 9 as `Se`; that branch uses only column 2 (`SNP`) and column 10 (`Pval`). Also, the allele-flipping block refers to `EAF` although the target reader names column 7 `EffectAF`. These are existing reader inconsistencies, not additional input columns; their reconciliation remains separate from this dictionary.

**SCZ:** `scz_gwas/<ancestry>_summ.tsv`, with ancestry codes `EUR`, `EAS`, `AFR`, and `LAT`. [`fit_four_methods.R`](real_data/scz/revision/fit_four_methods.R) and [`fit_baseline_subset.R`](real_data/scz/revision/fit_baseline_subset.R) expect exactly 14 columns:

| Position | Assigned name | Meaning / type |
| --- | --- | --- |
| 1–3 | `Chromsome`, `SNPID`, `Position` | Chromosome number, variant ID used to join ancestries, and physical position in bp. |
| 4–5 | `EffectAllele`, `NonEffectAllele` | Effect and other allele, as nucleotide strings. |
| 6–7 | `NonEffectAF_case`, `NonEffectAF_control` | Other-allele frequencies in cases and controls, numeric in [0, 1], as interpreted by the reader. |
| 8 | `INFO` | Numeric imputation-quality field, retained in the input table. |
| 9–11 | `Beta`, `SE`, `Pval` | Signed association coefficient, positive standard error on the same scale, and p-value. Supply the coefficient used to form the signed z-score `Beta / SE`, not an untransformed odds ratio. |
| 12–14 | `N_case`, `N_control`, `Neff` | Per-variant case count, control count, and supplied effective sample size. The fitting scripts read `Neff` rather than calculate it; its preprocessing definition must be confirmed. |

Height/SCZ SNPs are joined to the reference panel by position within a chromosome. The allele-alignment block reverses `Beta` and swaps alleles for reversed pairs, then retains variants matching the reference-panel allele labels. Other-ancestry p-values become annotation columns: missing values are filled with the column mean, followed by `-log(p)`, removal of constant columns, and standardization. Thus annotation p-values must be in (0, 1]; zero would produce infinity. Use `NA` for missing numeric entries; the scripts do not provide general imputation for missing target `Beta`, `SE`, coordinates, or sample sizes.

### Region files and model inputs

| Input | Structure / use |
| --- | --- |
| Height region files (`height_single_regions`, `height_ten_regions`) and `scz_candidate_regions/EUR_chr_<chr>.txt` | Headerless text, one region per row, two numeric columns: start and end in bp. Chromosome is identified by the filename. Fits select `start < Position < end`; preserve row order because saved region results are indexed in that order. Height fits write regions and read the EUR region file; SCZ fits require the prepared EUR region file. |
| UKBB `EUR/fourier_ls-all.bed` | Text LD-block table, despite the `.bed` suffix: read with a header, `chr` identifies chromosomes as `chr1`, etc.; columns 2–3 are interval start/end. The legacy real-genotype simulations use inclusive bounds. This is distinct from binary PLINK `.bed`. |
| UKBB `EUR_0.05maf/real_simulation/region_information/chr<chr>_common.txt` | Headerless table with at least three columns; column 3 is the SNP count used to select blocks with more than 100 SNPs. Rows must correspond to the chromosome-filtered LD-block table. Columns 1–2 are not interpreted by these simulation readers; retain the original block metadata. |
| Individual-level fitting inputs | `X`: numeric individuals-by-SNPs matrix; `Xk`: matching knockoff matrix; `y`: response vector in the same individual order; `R`: numeric SNPs-by-annotations matrix in the same SNP order. Synthetic experiments generate these objects in their drivers. |
| Summary-statistic fitting inputs | `Z`: signed SNP z-scores; `LD`: SNP-by-SNP correlation matrix computed from the selected reference genotypes; annotation matrix: one row per selected SNP. All share the same SNP order and allele orientation. Sample-size inputs are scalar or per-SNP according to the called function. `R` denotes a temporary correlation matrix in parts of the drivers but the annotation matrix in the annotation-informed package interface. |

Install the packages described in the [root README](../README.md) and the dependencies loaded by the selected scripts. The [dependency guide](environment/README.md) provides checked versions and installation sources, including `xtune`, `adaptMT`, `SNPknock`, `adaptiveKnockoff`, and `doMC`; it also describes the installation/load checks and provides software citations. Python utilities require Python 3.9 or later and use only standard-library modules.

Copy `config.example.R` to `config.local.R` to set input/output paths; see `config/paths.tsv` for required filenames. Validation workspace directories must contain the reference inputs and be writable.

To launch a script from the repository root, use `Rscript reproducibility/run.R <script-path> [arguments]`, where `<script-path>` is relative to `reproducibility/`.

For main Figure 2, run `simulations/annogk/continuous.R` for replicate IDs 1–100, then `simulations/annogk/figure2_result.R`. The reader uses the 300 files `heri_final_10_<h>_n_5000_p_1000_<i>.RData` (`h = 0.05, 0.1, 0.2`; `i = 1, …, 100`) under `annogk_results`, and exports a PDF, plotted values, and an input-file checklist.
